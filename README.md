## 1. Описание проекта и основа

**SpookyShop** — адаптивный многостраничный интернет-магазин костюмов, декора и аксессуаров для Хэллоуина. Проект КР №4 создан на основе собственного магазина **КР №3 (`kr3-responsive-shop`)**. HTML-разметка и адаптивные стили дополнены JavaScript, поэтому каталог, карточки товаров, поиск, фильтры, избранное, корзина и формы работают интерактивно.

Цель работы — применить на практике переменные, объекты, массивы, функции, циклы, методы массивов, DOM, обработчики событий, валидацию и `localStorage` в одном пользовательском сценарии.

**Технологии:** HTML5, CSS3, JavaScript без React, Vue, сторонних библиотек и сборщиков. Все действия с заказом демонстрационные: магазин не принимает платежи и не отправляет персональные данные на сервер.

## 2. Запуск проекта

1. Скачайте репозиторий или распакуйте архив и откройте папку `kr4-js-shop` в **VS Code**.
2. Запустите **Live Server** на файле `index.html` или из корня папки выполните:

   ```bash
   python3 -m http.server 5500
   ```

3. Откройте адрес `http://localhost:5500/index.html` (при использовании Live Server порт может отличаться).
4. Перейдите в каталог, выберите товар и попробуйте поиск, фильтры и избранное; добавьте товар, перейдите в корзину, примените промокод и нажмите «Перейти к оформлению». На `order.html` проверьте валидацию и подтверждение.
5. Для проверки кода откройте DevTools → **Console**. Для проверки DOM и CSS используйте вкладку **Elements**, для пошаговой отладки — **Sources / Breakpoints**.

> **Важно:** `localStorage` привязан к адресу сайта (включая порт). Если открыть магазин на другом порту, сохранённая корзина может не отображаться. Для последовательных проверок используйте один адрес.

## 3. Структура проекта

```text
kr4-js-shop/

├── product.html          # Универсальная карточка товара
├── cart.html             # Корзина: товары, количество, промокод и стоимость
├── order.html            # Оформление заказа: итог, форма и подтверждение
├── contacts.html         # Контакты, обратная связь и обратный звонок

│   ├── main.js           # Общие функции и DOM-компоненты
│   ├── store.js          # Состояние корзины/избранного и localStorage
│   ├── catalog.js        # Логика каталога и фильтров
│   ├── favorites.js      # Отображение избранного
```

Страница `product.html` использует параметр адреса `?product=id`. Например, `product.html?product=5` показывает товар «Тыква Джек LED». Отдельный HTML-файл для каждого товара не требуется. Оформление покупки разделено на **две страницы**: `cart.html` (товары, количество, промокод и общая сумма) → `order.html` (краткий итог без повторного списка товаров, контактные данные и подтверждение). Состав корзины и промокод сохраняются при переходе через `localStorage`.

## 4. Назначение JavaScript-файлов

| Файл | Что в нём реализовано |
|---|---|
| `data.js` | Общий массив `products` и исходные сведения о 10 товарах. |
| `main.js` | Форматирование и расчёт цен, поиск и сортировка на уровне данных, создание DOM-карточек, общие кнопки, счётчики, мобильная навигация и формы обратной связи. |
| `store.js` | Добавление, изменение количества и удаление товаров, избранное, промокод, безопасное чтение и запись `localStorage`, расчёт суммы корзины. |
| `catalog.js` | Состояние каталога, объединение условий поиска, категории, сортировки, цены, статусов и избранного, обновление карточек. |
| `favorites.js` | Отдельная страница избранного, обновление списка и пустое состояние. |
| `product.js` | Поиск товара по ID из URL, вывод данных, изображения, наличия, характеристик и действий. |
| `cart.js` | Отрисовка корзины, кнопки `+`, `−`, «Удалить», промокод, итоговая стоимость, кнопка перехода на `order.html` при непустой корзине. |
| `order.js` | Краткая сводка стоимости перед подтверждением (без повторения товаров), учёт промокода и пустое состояние. |
| `validation.js` | Проверка имени, электронной почты, телефона, даты доставки и согласия; сообщение об ошибке и успешная имитация заказа. |

Скрипты подключаются через `defer`. На страницах с общей логикой сначала загружается `data.js`, затем `store.js` и `main.js`, после них — JS-файл нужной страницы. Это позволяет использовать массив товаров и общие функции без повторения кода.

## 5. Данные о товарах

В `js/data.js` хранится **10 объектов** с одинаковыми основными свойствами:

| Свойство | Назначение |
|---|---|
| `id` | Уникальный идентификатор товара. |
| `title` | Название для каталога, поиска и корзины. |
| `category` | Категория: `costumes`, `decor`, `makeup`, `sweets`. |
| `price` | Исходная цена в рублях. |
| `discountPercent` | Скидка на отдельный товар в процентах. |
| `rating` | Рейтинг товара. |
| `isAvailable` | Наличие (`true` / `false`). |
| `isHit`, `isNew` | Признаки хита продаж и новинки. |
| `image` | Путь к фотографии. |
| `description`, `feature` | Описание и характеристика товара. |

Один массив используется сразу в каталоге, на главной, в избранном, в карточке товара и при подсчёте корзины. Это исключает расхождения между названиями, ценами и идентификаторами.

**Примеры:** костюм скелета (`id: 1`) стоит 2 490 ₽ до скидки 10%, то есть **2 241 ₽** после неё; искусственная кровь (`id: 6`) помечена как отсутствующая в наличии и недоступна для добавления в корзину.

## 7. Практическая работа №16 — массивы, поиск и расчёты

Вместо одного товара используется массив `products`. Реализованы и применяются:

- `getProductTitles()` — названия товаров с помощью `for...of`;
- `getAvailableProducts()` — фильтрация товаров в наличии через `filter()`;
- `searchProducts()` — поиск по части названия без учёта регистра;
- `filterProductsByCategory()` — выбор категории;
- `sortProductsByPrice()` — сортировка по цене с учётом индивидуальной скидки;
- `findProductById()` — поиск объекта по `id` через `find()`;
- `calculateTotalPrice()` — сумма исходных цен через `reduce()`;
- `countAvailableProducts()` — подсчёт доступных товаров циклом `for`;
- `calculateAveragePrice()` — средняя исходная цена товара;
- `getPreparedProducts()` — последовательное объединение поиска, категории и сортировки.

В коде используются **`for`, `for...of`, `forEach`, `map`, `filter`, `find`, `sort`, `reduce`**, условия `if` и логические операторы. Сортировка выполняется на копии массива, чтобы не изменять исходный порядок `products`.

В ходе практической расчёты проверялись через Console и временный вывод статистики на страницу. В итоговом интерфейсе результаты показываются через каталог, счётчики и корзину вместо учебной панели.

## 8. Практическая работа №17 — DOM, события и валидация

### Динамические карточки

Функция `createProductCard()` создаёт элементы карточки через `document.createElement()`, добавляет CSS-классы через `classList`, заполняет текст через `textContent` и вставляет узлы через `append()`. Для ID товара применяется `dataset.productId`. Каталог обновляется через `replaceChildren()` при изменении фильтров.

### Поиск, фильтрация и сортировка

В каталоге имеется **одна левая панель** со следующими инструментами:

- поиск по названию;
- выбор категории;
- сортировка по возрастанию/убыванию цены или названию;
- фильтр «Хиты продаж», «Новинки», «Со скидкой»;
- диапазон цены «От» / «До»;
- режим «Только избранное»;
- применение и сброс фильтров.

Поиск, категория и сортировка обновляют результат при вводе или выборе. Статус и диапазон цены применяются после отправки формы фильтров. Над карточками отображается количество найденных товаров; при отсутствии результатов показывается сообщение.

### События

Обработчики добавляются через `addEventListener()` для `input`, `change`, `click` и `submit`. Кнопки динамических карточек обрабатываются через делегирование событий с использованием `dataset` и `closest()`.

### Проверка форм

Форма оформления заказа находится на отдельной странице `order.html` и обрабатывается в `validation.js`:

- имя — не менее 2 символов без учёта пробелов по краям;
- e-mail — проверка простым регулярным выражением;
- телефон — 11 цифр, номер начинается с 7 или 8;
- дата — сегодняшняя или будущая;
- согласие — обязательная галочка;
- корзина — должна содержать хотя бы один товар.

Форма перехватывается через `preventDefault()`. Ошибки выводятся **под полями**, без `alert()`. При корректном заполнении на `order.html` показывается сообщение об успешной демонстрационной операции, поля очищаются и корзина становится пустой. Реального заказа и оплаты нет.

## 9. Самостоятельные доработки для повышенного уровня КР4

Практическая №18 предусматривает до **4 баллов** за базовую часть и до **4 баллов** за самостоятельное расширение проекта. В SpookyShop дополнительно реализованы:

1. **Корзина:** добавление товара с главной, из каталога и карточки; изменение количества кнопками `+` и `−`; удаление позиции и полная очистка.
2. **Сумма через `reduce()`:** стоимость корзины и число товаров пересчитываются при каждом изменении количества; учитываются скидки товаров.
3. **`localStorage`:** сохраняются состав корзины, избранные ID и применённый промокод. При чтении выполняется проверка структуры сохранённых данных.
4. **Избранное:** сердечки `♡/♥` на карточках, отдельная страница `favorites.html`, счётчик в шапке и быстрый фильтр каталога.
5. **Промокод `SPOOKY10`:** дополнительно уменьшает сумму корзины на 10%, отдельно показывает размер скидки и итог.
6. **Расширенная карточка:** рейтинг, наличие, метки «Хит», «Новинка» и «−10%», прежняя и новая цена, запрет покупки отсутствующего товара.
7. **Удобство интерфейса:** пустые состояния избранного и корзины, счётчики, сообщения о действиях, кнопка сброса фильтров, правильные переходы между страницами.
8. **Универсальная страница товара:** заголовок, изображение, характеристики, наличие и кнопки формируются из одного объекта товара; таблица характеристик адаптируется к мобильному экрану.
9. **Два шага оформления заказа:** `cart.html` позволяет изменить состав корзины и промокод; `order.html` показывает итоговую стоимость без повторного списка товаров и отдельную форму. Данные корзины передаются через `localStorage`, личные данные не сохраняются.
10. **Организация кода:** данные, обработка, состояние и отображение разделены по файлам; общая функция создаёт карточки для разных страниц; временный диагностический код удалён из основного интерфейса.

### Пример расчёта промокода

Если в корзине **2 костюма скелета**, то:

- цена одного после товарной скидки — **2 241 ₽**;
- сумма двух — **4 482 ₽**;
- дополнительная скидка `SPOOKY10` — **448 ₽** (`Math.round(4482 × 0,1)`);
- **к оплате: 4 034 ₽**.

Это демонстрирует функции, арифметические операции, `reduce()`, условия и обновление DOM.

## 10. Безопасность данных

- Пользовательский текст выводится через `textContent`, а не через `innerHTML`, чтобы не интерпретировать ввод как HTML-разметку.
- Для сообщений и карточек используются DOM-методы и заранее определённые свойства.
- Личные сведения из формы (имя, телефон, e-mail, комментарий) **не записываются в `localStorage` и не отправляются на сервер**.
- В `localStorage` сохраняются только технические данные: ID, количество товаров, избранное и промокод.
- Содержимое хранилища проверяется при чтении; недоступные и неизвестные товары не добавляются в корзину.
- `.gitignore` исключает служебные и потенциально чувствительные локальные файлы из новых Git-коммитов.

## 11. Адаптивность и доступность

Сохранена адаптивная основа КР №3: стили в `responsive.css`, изображения WebP и их адаптивные варианты, мобильное меню, перестройка каталога и формы для небольших экранов. Используются подписи `label`, альтернативные тексты `alt`, `aria-label`, `aria-live`, `aria-invalid`, видимый фокус и ссылка для перехода к основному содержимому. Карточки и фильтры доступны с клавиатуры.

Фон магазина — `images/fon.png`. Результаты Lighthouse в папке `lighthouse/` относятся к КР №3; после обновления проекта их следует перепроверить отдельно, а не считать актуальным аудитом КР №4.
